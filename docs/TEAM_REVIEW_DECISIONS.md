## 중요한 연결 관계

### 01 마음회의

`mobile/src/features/discussion/`의 화면만 바꾸는 문제가 아닙니다. 라우트, 컨트롤러, 로컬/네트워크 서비스, 타입, 서버 `discussions.py`, `mind_council.py`, DB 열, 프롬프트, 캐릭터 이미지, 테스트가 함께 움직입니다. 팀원 쪽 생각방 파일을 통째로 적용하면 현재 4인 회의와 입력 순서·리마인더 기능이 빠집니다.

### 02 작품 피드

팀원 신규 `CommunityFeed.tsx`와 온라인 화면의 공유 시트뿐 아니라 `backend/app/main.py`, `db.py`, DB 마이그레이션이 필요합니다. 서버 코드에 로그인·작품 소유권 검사와 게시용 필드 제한은 있지만, 이번 코드에서 게시 철회/게시글 삭제·신고·차단 경로는 확인되지 않았습니다. 채택하면 이 부분과 이미지 캐시/철회 동작을 검증할 필요가 있습니다. 원본 대화 공유 기능으로 확대하지 않습니다.

### 03 상담

`Counseling.tsx`, `config/counselors.ts`, 꽃 이미지 3개, API 타입, 서버 방/메시지 API, DB 테이블이 연결됩니다. 서버 설정으로 특정 username을 상담사 계정에 연결하는 방식이며, 계정이 없으면 신청 API가 503을 반환하도록 되어 있습니다. 사용자와 지정 계정 간 메시지 기능의 코드이지, 실제 전문가의 자격을 확인한 결과는 아닙니다. 기존 MVP 지침보다 범위가 넓으므로 구현에 앞서 사용자가 범위를 선택해야 하는 항목입니다.

### 04 감정 분류

`emotion_classifier.py`, `emotion_art.py`, `ai.py`, 추가 환경 설정, 감정 테스트, `scripts/emotion_server/` 및 모델 파일이 연결됩니다. 이 코드는 채팅 답변 전체를 바꾸는 방식이 아니라 승인한 그림 이야기를 분류해 그림 연출에 참고하는 방식입니다. 분류 서버 오류/낮은 확신도/모델 간 불일치 때는 참고를 생략하도록 작성되어 있습니다. 별도 torch/transformers 의존성은 버전이 고정되어 있지 않아 채택 시 호환성 확인과 별도 잠금이 필요합니다. 모델은 실행하지 않았으며 분류 정확도도 검증하지 않았습니다.

### 08 내부 표기 제거 + 감정 참고의 조합

팀원 `ai.py`, `art_story.py`, `main.py`를 통째로 적용하면 내 최신의 `clean_art_story` 호출과 전용 테스트가 빠집니다. 04를 채택하더라도 이 정리 경계를 보존하면서 감정 참고 로직만 넣어야 합니다.

### 09 개발 환경·10 메뉴

`mobile/src/services/api.ts`에는 팀원 신규 상담 타입과 내 최신 저장 키 분리가 겹칩니다. 타입은 추가하면서 `STORAGE_PREFIX`는 유지하는 식의 조합이 필요합니다. `OnlineApp.tsx`는 최신 '마음' 경로/라벨과 팀원 신규 탭·공유 시트가 겹칩니다. `features/App.tsx`의 삼항 렌더링을 이전 `문자열 && 컴포넌트`로 되돌릴 이유는 없습니다.

### 11 DB

두 마이그레이션은 ID가 서로 다르지만 모두 `g116_discussions`에서 갈라집니다. 파일 두 개를 그대로 놓으면 Alembic head가 두 개가 되어 기존 `upgrade head` 실행 방식과 충돌합니다. 선택된 기능에 맞는 후속 마이그레이션 또는 병합 리비전을 별도로 설계해야 합니다. 기존 DB 덮어쓰기·과거 DB 복사·무조건 downgrade는 하지 않습니다.

### 12 문서·설치 정보

`package.json`, `package-lock.json`, `requirements.lock.txt`는 줄바꿈을 제외한 내용이 같습니다. 기존 앱 패키지를 업그레이드할 필요가 생긴 차이는 아닙니다. `mobile/expo-env.d.ts`는 Expo가 만드는 파일이므로 기능 선택 대상과 구분합니다. 실행 문서/PROGRESS는 예전 버전으로 교체하지 않고 신규 채택 내용만 추가합니다.
