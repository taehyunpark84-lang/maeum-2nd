### 03 상담

`Counseling.tsx`, `config/counselors.ts`, 꽃 이미지 3개, API 타입, 서버 방/메시지 API, DB 테이블이 연결됩니다. 서버 설정으로 특정 username을 상담사 계정에 연결하는 방식이며, 계정이 없으면 신청 API가 503을 반환하도록 되어 있습니다. 사용자와 지정 계정 간 메시지 기능의 코드이지, 실제 전문가의 자격을 확인한 결과는 아닙니다. 기존 MVP 지침보다 범위가 넓으므로 구현에 앞서 사용자가 범위를 선택해야 하는 항목입니다.

사용자 설명 및 선택 확정: 상담은 미래 확장을 위해 만든 화면이며, 팀원 화면의 구성·이미지·흐름을 그대로 채택합니다. 실제 상담 서버, 담당자 계정 연결, 상담 DB/메시지 운영 기능은 이번 반영 범위에 포함하지 않습니다. 기존 코드의 서버 요청 부분은 화면 전용 범위에 맞게 분리하고, 연결이 필요한 조작은 준비 중 상태와 이유를 표시합니다. 담당자가 실제 접속했거나 메시지가 전달된 것처럼 표시하지 않습니다. 11번 DB 선택 시에도 상담 테이블을 자동으로 포함하지 않습니다.

### 04 감정 분류

`emotion_classifier.py`, `emotion_art.py`, `ai.py`, 추가 환경 설정, 감정 테스트, `scripts/emotion_server/` 및 모델 파일이 연결됩니다. 이 코드는 채팅 답변 전체를 바꾸는 방식이 아니라 승인한 그림 이야기를 분류해 그림 연출에 참고하는 방식입니다. 분류 서버 오류/낮은 확신도/모델 간 불일치 때는 참고를 생략하도록 작성되어 있습니다. 별도 torch/transformers 의존성은 버전이 고정되어 있지 않아 채택 시 호환성 확인과 별도 잠금이 필요합니다. 모델은 실행하지 않았으며 분류 정확도도 검증하지 않았습니다.

사용자 선택 확정: 팀원의 감정 분류·그림 연출 참고 기능과 관련 로컬 감정 서버/모델 연결을 채택합니다. 기준 점수 0.7은 모델 출력 점수이며 실제 정확도 70%를 뜻하지 않습니다. 선택이 끝난 뒤 별도 의존성 호환성·실행·오류 시 참고 생략·GPT 판단 일치 조건을 검증하며, 현재 단계에서는 기록만 합니다.

사용자가 내 버전으로 반영하도록 확정했습니다. 내 최신의 내부 표기 제거 함수·호출 경계·전용 테스트를 유지하고, 04에서 채택한 팀원 감정 분류 기능은 이 정리 처리를 보존하는 방식으로 조합합니다. 실제 사용자 이야기의 내용이나 기존 저장 데이터를 일괄 변경하는 선택으로 확대하지 않습니다. 현재 단계에서는 결정만 기록합니다.

10 사용자 선택 확정: 온라인 하단 메뉴를 **공간 · 마음 · 작품 피드 · 상담 · 갤러리** 순서로 구성합니다. 마음은 내 최신 4인 회의에 연결하고 이름은 '마음'을 유지합니다. 작품 피드는 02의 선택을 따르고, 상담은 03에서 정한 미래 확장용 화면 범위를 따릅니다. 공간·갤러리의 기존 동작은 유지합니다. 서버 없는 기존 시연 앱의 메뉴 변경으로 자동 확대하지 않습니다.

### 11 DB

두 마이그레이션은 ID가 서로 다르지만 모두 `g116_discussions`에서 갈라집니다. 파일 두 개를 그대로 놓으면 Alembic head가 두 개가 되어 기존 `upgrade head` 실행 방식과 충돌합니다. 선택된 기능에 맞는 후속 마이그레이션 또는 병합 리비전을 별도로 설계해야 합니다. 기존 DB 덮어쓰기·과거 DB 복사·무조건 downgrade는 하지 않습니다.

사용자 선택 확정: 내 최신 마음회의 DB 구조를 유지하고, 작품 피드의 게시글·반응·댓글 저장 구조만 후속 변경으로 추가합니다. 03의 화면 전용 범위에 따라 상담 테이블은 제외합니다. 팀원의 개인 기록이 담긴 DB는 복사하지 않습니다. 실제 적용 전 검토 worktree의 로컬 DB를 백업하고, 적용 후 기존 기록 보존·스키마·무결성·외래 키를 검사합니다. 현재 단계에서는 선택만 기록하며 DB를 변경하지 않습니다.

### 12 문서·설치 정보

`package.json`, `package-lock.json`, `requirements.lock.txt`는 줄바꿈을 제외한 내용이 같습니다. 기존 앱 패키지를 업그레이드할 필요가 생긴 차이는 아닙니다. `mobile/expo-env.d.ts`는 Expo가 만드는 파일이므로 기능 선택 대상과 구분합니다. 실행 문서/PROGRESS는 예전 버전으로 교체하지 않고 신규 채택 내용만 추가합니다.
