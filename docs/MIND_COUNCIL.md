# 마음 — 네 감정의 회의

하단 온라인 탭은 **공간 · 마음 · 갤러리**입니다. 기존 공간, 계정, 채팅, 사운드, 작품 생성·저장, 갤러리 및 로컬 시연 피드는 유지합니다. 서버 없는 모드의 기존 내 기록·공감 피드 탭도 유지하고 생각방 이름만 마음으로 바꿨습니다.

## 회의 흐름

시작 화면에서 안건을 쓰면 사회자 → 슬픔·불안·분노·기쁨의 1차 의견 → 네 패널의 논쟁 → 사회자 연결 → 대표 패널 질문으로 자동 진행합니다. 첫 질문자는 슬픔이며, 다음 라운드마다 불안·분노·기쁨으로 순환합니다. 패널이 하나의 결론에 억지로 합의하지 않도록 요청합니다.

대표 질문 뒤에는 사용자 답변을 기다립니다. 답변 전에는 추가 발언을 생성하지 않습니다. 답변을 보내면 사회자가 이어받아 다음 라운드를 진행합니다. 새 회의에는 이어하기·중지·종료 버튼을 두지 않았고, 오류 때만 다시 시도합니다. 상단 +는 시작 화면을 다시 보여주며, 새 안건을 실제로 제출하기 전에는 이전 안건을 바꾸지 않습니다.

2026-11-27 단계 구분 보완: **패널별 1차 의견**은 아이보리 영역 안의 패널별 카드(짧은 2~3문장을 줄바꿈)로, **감정들의 논쟁**은 보라색 영역 안의 작은 아이콘·이름·한 문장 반박으로 표시합니다. 이어지는 사회자 브리지와 대표 패널 질문도 별도 제목/질문 카드로 구분합니다. 논쟁은 새 의견을 다시 발표하지 않고 같은 라운드의 다른 패널 주장을 지목해 반박하도록 지시합니다. 모바일에서는 문장을 잘라 숨기지 않으므로 화면 폭·글자 크기에 따라 한 문장이 여러 화면 줄로 보일 수 있습니다.

채팅 입력은 대표 질문 완료 후에만 열립니다. 자동 발언 중에는 읽기 전용이고 전송도 차단합니다. 컨트롤러·오프라인 어댑터·서버 API가 모두 같은 순서를 검사하며, 단계 중 직접 API로 입력해도 409로 거부하고 라운드를 초기화하지 않습니다. 기존 3인 방식의 의견 개입 동작은 유지합니다. 각 발언의 단계는 서버 응답 및 화면용 데이터에 포함하며, 과거 4인 기록은 원문을 수정하지 않고 순서에서 단계를 복원합니다. DB 마이그레이션은 추가하지 않았습니다.

다른 탭이나 앱 백그라운드로 나가면 요청을 취소하고, 돌아오면 저장된 최근 라운드를 표시합니다. 도중에 나간 경우 남은 발언을 자동으로 이어가며, 사용자 답변 대기 상태였다면 계속 기다립니다. 설정의 이전 라운드 표시를 켜면 같은 안건의 전체 대화를 볼 수 있습니다.

이전 3인 생각방 기록은 버전 1로 보존합니다. 기존 활성 기록이 있다면 새 시작 화면의 **기존 생각방 대화 보기**로 이전 방식의 읽기·중지·이어하기·의견 개입·기록 표시 기능을 사용할 수 있습니다. 새 안건을 시작하면 버전 2 회의가 됩니다. 과거 기록을 삭제하거나 4인 패널의 발언으로 바꾸지 않습니다.

## 프롬프트와 리마인더

`backend/app/prompts/council/`에 사용자 제공 공통·4인 시스템·리마인더 txt를 저장했습니다. 분노 프롬프트의 마지막 강제 지적 규칙은 확인된 모순을 구체적으로 지적하되 확인되지 않은 잘못을 지어내지 않는 조건으로 보완했습니다. 나머지 제공 문구와 패널별 리마인더는 보존했습니다. 공통 상위 규칙에서 사용자 인격 대신 판단·행동을 비판하고, 불확실성을 사실로 단정하지 않으며, 긴급 위험에는 논쟁보다 안전을 우선하도록 했습니다. 위험 단어 횟수에 따른 강제 종료 규칙은 추가하지 않았습니다.

각 패널 호출의 `instructions`에는 공통·개별 페르소나와 현재 단계가 들어갑니다. 최근 발언 및 사용자 답변 뒤에 별도의 신뢰된 `developer` 메시지로 해당 패널의 리마인더를 붙입니다. 리마인더를 사용자 발화 원문이나 DB 메시지에 합쳐 저장하지 않습니다. 사회자는 4인 패널용 리마인더를 받지 않습니다.

**페르소나 리마인더는 기본 켜짐**입니다. 끄면 다음 패널 API 요청에서 추가 developer 메시지가 실제로 빠지며, 기본 시스템 페르소나는 유지합니다. 변경은 계정별로 저장합니다. 생성 중 변경하면 revision과 리스를 갱신해 이전 설정의 늦은 응답이 저장되는 것을 막습니다. 앱은 해당 응답을 취소하고 새 설정으로 재개합니다. 기본 시스템 페르소나가 있으므로 끈 직후 말투가 즉시 달라지지 않을 수 있지만 추가 리마인더 전송 여부는 실제로 바뀝니다.

## 검증

- 기존 회귀 테스트와 새 버전의 전체 사이클·대기·질문자 순환·탭 복귀·취소/중복 방지·리마인더 설정 저장 및 실제 provider payload ON/OFF를 검증합니다. 실행 결과는 `PROGRESS.md`의 최신 항목을 확인합니다.
- `scripts/verify-council-live.py --live`는 합성 안건과 별도 tmp DB로 실제 모델 14회 호출을 수행합니다(API 비용 발생). 11개 발언 1사이클과 켜짐→꺼짐→켜짐 요청 변경을 실제 모델로 확인했습니다. 개인 대화·운영 DB·개발 사용자 데이터는 검증에 사용하지 않습니다. 결과는 `tmp/council/live-*/report.json`입니다.
- 최초 실제 모델 검사에서는 두 번째 요청이 HTTP 502로 실패했습니다. 검증용 TestClient를 서버와 같은 단일 이벤트 루프로 수정한 뒤 재실행하여 14개 발언이 통과했습니다.
- 390px 보조 웹 화면에서 시작 카드·자동 진행·답변 대기·설정 저장·갤러리 이동 후 대화 복귀·새 안건 화면을 확인했습니다. 웹 확인을 Android/iOS 실기기 검증으로 간주하지 않습니다.
- 실제 Android/iOS 화면·키보드, 휴대폰에서의 새 실제 AI 전체 사이클은 아직 별도 확인이 필요합니다. Android Hermes export는 앱 설치와 구분합니다.

단계 보완 후 검증: 백엔드 전체 58개·모바일 전체 56개, typecheck/lint, Android Hermes export 통과. 자동 테스트에서 두 라운드 모두 의견 4개/논쟁 4개/질문 1개와 단계별 입력 차단을 확인했습니다. 실제 AI 14회 검증은 의견 2~3문장 줄바꿈, 다른 패널을 지목한 90자 이내 논쟁, 질문 뒤 대기와 리마인더 ON/OFF를 확인했습니다(`tmp/council/live-1795751812184809000/report.json`). 390px 시연 미리보기에서 의견/논쟁 구분 및 입력의 readOnly=true→false 전환을 확인했습니다. 현재 실행 중인 로컬 API는 자동 재시작하지 않았으므로 코드 반영을 위해 API와 Expo를 기존 PowerShell 창에서 재시작하세요.
