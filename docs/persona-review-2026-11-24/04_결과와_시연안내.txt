검토 결과 — 토리와 도담 / 2026-11-24

선정 이유
6개 설정을 비교하면 토리와 도담은 말투(반말/존댓말), 리듬(경쾌함/고요함), 관심(구체적인 재미/생각과의 거리)의 세 축에서 대비된다.
모든 캐릭터를 실제 모델로 경쟁 평가한 결과는 아니다. 6개 설정을 읽어 선정한 뒤 이 두 캐릭터를 집중 검증했다.

최종 컨셉
토리: 작은 발견과 장난스러운 수다. 가벼운 새 주제 첫 응답에 다람쥐다운 상상을 짧게 연결하고, 후속 턴은 장식을 쉬며 직접적으로 편들어 주는 친구.
도담: 생각과 거리를 두는 고요한 대화. 경험 자체를 조용히 받아준 뒤, 자책이 나올 때 실제 일과 자신에게 붙인 평가를 나누어 보는 상대.
둘 다 애도/실질적인 요청/거절/긴급한 위험에서는 개성보다 사용자의 필요를 우선한다.

실험과 수정
원본(before) → 1차(v1: 관점 분리) → 2차(v2: 말투/사실성/안전 전제 보완) → 3차(v3: 토리 첫인상 강화) → 최종(after/v4: 화자 혼동 보완).
기존 6개 시나리오에 3차부터 새로운 운동화 주제를 추가했다. 새 주제는 프롬프트 예시에 넣지 않았다.
최종안 전체 7개 시나리오와 첫인상/거절·애도의 독립 반복을 확인했다.
모델과 인자는 로컬 앱 서버 설정의 gpt-6.1-terra, reasoning low, verbosity low, max_output_tokens 2200을 유지.
직접 만든 합성 입력만 사용. 실제 사용자 대화를 읽지 않았고 DB/metrics를 쓰지 않았다. 실제 OpenAI 유료 호출이다.
각 호출의 모든 모델 입력/지침/응답/토큰은 run 폴더에 보존. 시작/종료 시간은 KST.

최종 반복에서도 청자 표현은 유지. 개성 강화는 특히 가벼운 이야기에서 관찰됐고, 깊은 자책에는 차이가 제한적임.

관찰된 개선
1. 최종안에서 토리는 가벼운 주제 첫 답변에 가상의 다람쥐 시점을 드러냈고 도담은 차분하게 경험을 되짚었다.
2. 하루를 잘못 보낸 것 같은 자책에서 토리는 실제 좋았던 순간을 짚어 직접 편들고, 도담은 하루와 평가 사이의 거리를 제안했다.
3. 최초 대화의 '둘이 함께 한참 웃었다' 같은 사실 확대는 최종 게임 시나리오에서 줄었다. 미래의 모든 응답에서 사라진다는 뜻은 아니다.
4. 중간안의 화자 혼동은 마지막 수정 후 본시험과 독립 반복에서 '지쳤다는 말 그대로 들을게'라는 청자 표현으로 바뀌었다.
5. 질문/조언/비유 거절, 한 문장 회의 문안, 두 문장 문자, 가상 정체성 확인에 응답했다. 실제 도움을 요청하면 차이를 억지로 만들지 않는다.
6. 긴급 위험 단일 사례에서는 캐릭터 놀이 대신 사람의 도움과 위험물에서 거리 두기를 우선했다. 지역별 위기 안내 및 전반적 안전 설계는 별도 검토 대상이다.

남은 한계와 문제 (완전 해결로 보고하지 않음)
- 자책/불안에서는 두 캐릭터 모두 '한 번의 실수가 능력 전체를 뜻하지 않는다'는 비슷한 위로에 수렴했다. 이 영역은 말투 외 차이가 작다.
- 토리의 '도토리 창고'가 서로 다른 가벼운 주제에서 반복되는 경향이 관찰됐다. 같은 대화에서 계속 붙이지는 않았지만 장기적인 표현 다양성은 더 평가해야 한다.
- 토리가 후속 턴에서 '잘못 보낸 하루는 아니야' 같은 일반적 허용으로 돌아가는 경향은 남아 있다.
- 도담은 일상 대화에서 단순 반영에 머물 수 있고, 자책 시 구분을 가르치는 인상도 완전히 제거됐다고 볼 수 없다.
- 최종 반복의 도담 답변에는 사용자가 명시하지 않은 '하루가 끝나니'라는 시간적 추정도 남았다. 사실 확대가 전부 해결됐다는 결론은 내리지 않는다.
- 3턴짜리 대화 중심이고, 과거 다른 공간의 합성 기록을 넣은 정체성 사례는 1개뿐이다. 실제 장기 누적 요약, 여러 성별 설정, 실제 사용자 다양한 표현을 전부 검증하지 않았다.
- 사용자가 애도를 말하거나 답변 형식을 좁히면 차이가 작아지는 것이 의도된 동작이다. 모든 상황에서 극단적으로 다르게 답하는 것이 목표는 아니다.
- 동일 사용자 발언/모델/설정/초기 문맥을 유지했지만 2턴 이후는 각자의 실제 응답을 이어가므로 전체 입력이 동일하지 않다. 고정 시드/대규모 통계/블라인드 사용자 평가는 하지 않았다.
- 품질 평가는 기록을 읽은 작업자의 판단이다. 성공 호출 횟수는 품질 합격률이 아니다.

공정한 시연 조건
일반 앱은 사용자 단위로 여러 공간의 과거 대화를 공유한다. 한 계정에서 토리 후 도담으로 이동하면 도담이 토리의 앞선 대화를 참고하므로 동일 초기 조건이 아니다.
기존 사용자 기록을 지우지 말고, 별도의 두 새 시연 계정 또는 이 평가 스크립트의 독립 기록을 사용한다.
mock 모드의 고정 응답은 이번 프롬프트 검증 결과가 아니다. 실제 AI 모드에서 실행해야 한다.

반영 범위
로컬 backend/app/prompts/forest.txt, temple.txt와 mobile/src/config/assets.ts의 두 컨셉/설명/페르소나를 수정.
backend/app/tuning.py의 PROMPT_VERSION을 persona-2026-11-24-v4로 변경. 모델/추론 설정은 유지.
common.txt, SAFETY, 나머지 4개 공간, 그림 기획/생성, 생각방 프롬프트는 변경하지 않음.
공간 프롬프트는 완성 그림 소개(describe_art)에도 사용하므로 토리/도담의 새 작품 설명 말투에도 영향이 있다. 실제 이미지 생성/완성 작품 설명은 이번에 호출하지 않음.
VM 배포, 서버 재시작, APK 재빌드/설치, 휴대폰 화면 검증은 하지 않음. 운영 앱에 반영 완료됐다는 의미가 아니다.
로컬 프롬프트는 chat_instructions가 요청마다 읽는다. 버전 메타데이터 반영은 API/worker 재시작이 필요. 원격 서버는 해당 수정 파일 배포가 필요하다.
